# React Weather

A small weather application built with React, Vite, React Router, Tailwind CSS utilities, and a custom animated background system.

The app currently has three main areas:

- `Home`: asks the browser for geolocation and shows the raw coordinate data.
- `Weather`: loads current weather and a short forecast from OpenWeather.
- `App`: a debug panel for forcing season, time of day, and weather scenes.

## Tech Stack

- React 19
- Vite
- React Router
- Tailwind CSS utilities inside JSX
- Custom CSS animations in `src/index.css`
- OpenWeather API
- Browser Geolocation API

## Getting Started

1. Install dependencies:

```bash
npm install
```

2. Start the dev server:

```bash
npm run dev
```

3. Build for production:

```bash
npm run build
```

## How the App Works

### 1. Routing and Layout

- `src/App.jsx` sets up `BrowserRouter` with the project `basename`.
- `WeatherBackground` is mounted once at the app shell level, behind all pages.
- `Header` is also mounted once, so navigation stays consistent across routes.

### 2. Geolocation Flow

- `Home.jsx` calls `getCurrentPosition()` from `src/services/getCurrentPosition.js`.
- The service wraps the browser Geolocation API in a Promise.
- Success returns the raw `GeolocationPosition`.
- UI-ready rows are generated by `getPositionDetails()` from `src/utils/geolocationDisplay.js`.

### 3. Weather Dashboard Flow

- `WeatherPage.jsx` is intentionally small now and mostly composes child components.
- `useWeatherDashboard()` handles:
  - city input state
  - current weather request
  - forecast request
  - loading / success / error states
  - caching the latest successful result in localStorage
- `WeatherOverview` renders the main weather panel.
- `ForecastStrip` renders the compact hourly forecast.
- `WeatherCard` renders a single forecast entry.

### 4. Theme and Background Logic

- `weatherTheme.js` converts weather data into a visual theme:
  - season
  - time of day
  - scene type
  - light/dark mode
- `useStoredWeatherTheme()` listens for saved weather or debug-theme changes.
- `WeatherBackground.jsx` only connects theme state to the scene renderer.
- `components/weather-background/sceneUtils.js` calculates atmosphere values:
  - cloud density
  - rain intensity
  - snow intensity
  - wind direction and strength
  - optional birds / shooting stars
- `components/weather-background/BackgroundScene.jsx` renders the right scene layers.
- `src/index.css` contains the actual animation definitions and visual styling.

### 5. Debug Theme Flow

- `AppPage.jsx` reads and writes the debug override from localStorage.
- When debug mode is enabled, live weather visuals are replaced by the chosen:
  - season
  - time of day
  - weather effect
- This makes it easy to test all backgrounds without waiting for real weather.

## localStorage Keys

The app currently persists a few values in localStorage:

- `weather:last-city`: last searched city name
- `weather:last-data`: latest successful current-weather payload
- `weather:last-forecast`: latest successful forecast payload
- `weather:theme-debug`: debug theme override

## Where to Change Things

- Change search UI: `src/components/SearchBar.jsx`
- Change weather page layout: `src/components/weather/*`
- Change background logic: `src/components/weather-background/*`
- Change animation visuals: `src/index.css`
- Change API fetching / persistence: `src/services/weatherApi.js`
- Change theme rules: `src/utils/weatherTheme.js`
- Change navigation behavior: `src/components/Header.jsx` and `src/hooks/useLiquidNav.js`

## Notes

- The OpenWeather API key is currently stored in `src/services/weatherApi.js`.
- Background visuals use a mix of OpenWeather data and local debug overrides.
- Most page files are now intentionally thin; heavy logic lives in hooks, utils, and focused child components.
